## 2. 已建立的整体流程

```text
独立预训练 ONet
    ↓ 加载并冻结参数
目标图片 → 灰度亮度 → 目标墨量 C
    ↓
初始化连续墨点 coords → ONet 分别编码 x、y → 初始软图 H
    ↓
拼接 H 和 C → PNet 输出二维位移场
    ↓
按每个墨点所在格子取位移 → 原坐标 + 位移
    ↓
ONet + 可微渲染器 → 移动后的软图
    ↓
高斯平滑后的色调损失 L_T
    ↓
backward 求梯度 → Adam 更新 PNet 参数
```

当前每次训练更新都从同一组初始坐标和初始软图出发，训练 PNet 给出更有效的一次移动。训练 100 次，不等于墨点连续移动 100 次；论文式多步展开仍待实现。

## 3. Python 与 PyTorch 学习记录

已逐步讨论并理解：

- `if __name__ == "__main__":`：直接运行文件时执行脚本主体；被其他文件导入时不自动执行主体。
- `class ONet(nn.Module)`：继承模块基类；括号中的 `nn.Module` 是父类，不是普通参数类型声明。
- `__init__`、`super().__init__()`、`forward`、模型实例及调用。
- 位置参数和关键字参数，如 `F.one_hot(indices, num_classes=dim)`。
- 张量形状 `(6400,)` 是有 6400 个元素的一维张量，末尾逗号不代表第二维为 0；`(6400, 1)` 是二维张量。
- 维度编号从 0 开始。`dim=1` 指沿第 1 维操作，不是每 1 行分组。
- 切片 `chunk[:, 0:1]` 保留坐标列维度；`chunk[:, 0]` 会少一个维度。
- `unsqueeze` / `None` 插入长度为 1 的维度；`squeeze(dim)` 只会移除长度为 1 的指定维度。
- 广播从末维对齐，每对维度相同或其中一个为 1 才能兼容；逐元素乘法不会直接把维度大小相乘。
- `probabilities[sample_ids, indices]` 按成对的样本下标、真实类别下标取值；`indices` 不是模型预测的最大值下标。
- `with` 是上下文管理语法，不是新建普通局部变量作用域。
- `torch.no_grad()` 使其中新执行的运算不记录普通反向求导图，不会清空已有梯度，也不会使之前构建的图失效。
- `loss.backward()` 求导并累积梯度；`optimizer.step()` 才更新参数；`zero_grad()` 清理旧梯度。
- 模型输出由输入和当前权重计算得到；最初随机的是权重，预测值不是每次独立随机生成。
- `train()` / `eval()` 切换模块行为，不等同于开始训练或关闭求导。
- 卷积通道数表示特征数量，空间下采样由步长等决定；64 通道变 32 通道不等于图像缩小一半。
- 可训练的 3×3 卷积核与损失函数中固定的高斯核用途不同。
- 更新参数后，旧 `loss` 数值不会自动变化，需要重新前向计算。
- 字典、`.items()`、路径拼接、图像保存，以及墨量转亮度。

## 4. ONet：从 L1 实验到交叉熵版本

### 4.1 模型和标签

`onet.py` 定义四个全连接层，三个隐藏层后使用 ReLU：

```text
(N, 1)
 → Linear(1, hidden) → ReLU
 → Linear(hidden, hidden) → ReLU
 → Linear(hidden, hidden) → ReLU
 → Linear(hidden, dim)
 → (N, dim) 位置分数 logits
```

历史默认 `hidden=256`、`dim=64`。横、纵坐标共用同一个 ONet，分别编码一个坐标轴，而非直接预测全部 64×64 个像素。

训练点由整数样本编号生成：

```python
sample_ids = torch.arange(dim * samples_per_bin)
xs = (sample_ids.float() / samples_per_bin).unsqueeze(1)
indices = sample_ids // samples_per_bin
targets = F.one_hot(indices, num_classes=dim).float()
```

64 类、每区间 100 个采样点时，坐标为 0、0.01、…、63.99，共 6400 个。标签表示坐标所在格子的编号，不是真实图像的墨点分布。

当前训练使用 `F.cross_entropy(predictions, indices)`；损失接收原始分数和整数类别。评估及渲染时再使用 softmax 转成概率。

### 4.2 历史实测

| 实验 | 更新次数 | 损失 | 训练准确率 |
|---|---:|---:|---:|
| L1 早期实验 | 100 | 0.0274169 | 2.40625% |
| L1 延长训练（另一轮） | 1000 | 0.0228488 | 4.31250% |
| 交叉熵实验 | 1000 | 1.5531117 | 76.39062% |
| 交叉熵实验 | 5000 | 0.5295070 | 95.57812% |

L1 下稀疏 one-hot 标签的多数位置为零，整体误差较小不代表分类正确；全零输出的平均绝对误差仅为 1/64。这解释了为什么不能只看损失判断成功。交叉熵直接鼓励正确类别在类别竞争中获胜，当前实验提升明显，但不能据此认定论文 L1 方法本身无效。

合成坐标数据本来就适合训练坐标编码器；效果差不能简单归因于“没有用真实图像”。

5000 次交叉熵训练后：

- 正确类别平均概率：0.6308666。
- 偏移半个采样间距后的测试点：0.005、0.015、…、63.995。
- 6400 个测试坐标准确率：95.14062%。
- 测试正确类别平均概率：0.6306646。
- 历史检查点：`checkpoints/onet_64_ce_5000.pth`。

准确率和损失可能短期反向变化：准确率只看最大分数类别，交叉熵看所有样本的正确类别概率。准确率高也不意味着每个预测都接近 one-hot。

边界局部检查：

| 坐标 | 类别 12 概率 | 类别 13 概率 | 预测类别 |
|---|---:|---:|---:|
| 12.95 | 0.645738 | 0.354116 | 12 |
| 12.995 | 0.494597 | 0.505277 | 13 |
| 13.005 | 0.460089 | 0.539789 | 13 |
| 13.05 | 0.313871 | 0.686019 | 13 |

观察到边界附近平滑过渡及错分；这是局部证据，不能仅凭几个点代表所有区间。

## 5. 可微渲染器

`render.py` 已实现 `render_one_dot` 和支持分块的 `render_dots`。

约定每行坐标为 `[x, y]`，x 对应列，y 对应行。设图像边长为 S，本批点数为 K：

| 张量 | 形状 | 含义 |
|---|---|---|
| coords | (N, 2) | 全部连续墨点坐标 |
| chunk | (K, 2) | 一批坐标，最后一批可能少于分块大小 |
| x_encoding | (K, S) | 各点在列方向的位置概率 |
| y_encoding | (K, S) | 各点在行方向的位置概率 |
| dot_images | (K, S, S) | 每个点单独的二维软图 |
| uncovered | (S, S) | 所有已处理点都未覆盖的程度 |
| 最终软图 | (S, S) | 合成后的墨量图 |

关键广播：

```python
dot_images = y_encoding[:, :, None] * x_encoding[:, None, :]
# (K, S, 1) * (K, 1, S) → (K, S, S)
```

等价于对每个点分别做外积：

```text
dot_images[k, row, col] = y_encoding[k, row] * x_encoding[k, col]
```

单点图的元素和约为 1；多点通过 `H = 1 - ∏ᵢ(1 - Hᵢ)` 合成，整图的和不必等于 1，也不必等于墨点数量。重叠不会通过简单相加得到大于 1 的墨量。

历史单点验证：

- 图像形状：(64, 64)。
- 第 32 行、第 12 列值：0.5753315。
- 全图和：0.99999994。
- 对该像素求导，x 梯度为 0.0397942，y 梯度为 −0.2292349。

当前渲染结果是连续灰度软图，不是严格二值图。`dot_images` 保留逐点维度，也不是把合成图中最大的 N 个值直接当作 N 个墨点。

## 6. PNet 与坐标移动

`pnet.py` 当前结构：

1. 将初始半调图 H 和目标墨量图 C 沿通道拼接，得到 (B, 2, S, S)。
2. 输入 3×3 卷积映射到可配置的特征通道数。
3. 两层特征卷积及 ReLU。
4. 两次 stride=2 卷积下采样。
5. 双线性插值恢复输入空间尺寸，使用 align_corners=False。
6. 两层卷积预测头输出 (B, 2, S, S)，分别为横、纵位移。

64 特征通道和 3×3 卷积来自此前论文核对；具体堆叠层数、两级下采样和插值实现是当前工程选择，不能宣称逐层等同官方实现。当前没有专门将输出头初始化为零，因此初始位移不保证接近零。

`move_dots` 当前仅支持单张图：

- 对原坐标 floor 后转整数，得到查表用行列下标。
- 从运动场取出每个点的 Δx、Δy。
- 将位移加到原连续坐标上。
- 将新坐标截断到 [0, width−1]、[0, height−1]。

整数下标不可微，但取到的运动场值仍能向 PNet 传梯度。当前没有实现多图变长点集批处理。

## 7. 损失函数与论文差异

`losses.py` 已实现：

- 一维高斯权重归一化，再通过外积生成二维固定核。
- 镜像填充和卷积平滑。
- 对平滑后的 H 与 C 求差，展平每张图，计算向量 L2 范数，再按图像批次求平均。

当前 L_T 不是 MSE。默认核大小 11、sigma=1.5、镜像填充是当前实现设置；不能将论文评估时的 11×11 高斯核直接当作训练设置全部得到确认。

此前整理的完整目标为 `L_P = L_T + 0.04 L_S + 0.08 L_R`。目前：

| 损失 | 状态 |
|---|---|
| L_T：色调损失 | 已实现并用于训练 |
| L_S：结构损失 | 未实现，具体结构度量还需进一步核对 |
| L_R：逆半调重建损失 | 未实现，尚未接入预训练逆半调网络 |

用户已同意先用 L_T 跑通流程。当前交叉熵 + softmax ONet 也是学习实现与论文原 L1 编码拟合的区别，需要保留后续对照实验。

## 10. 分辨率和 GPU 规划

用户计划迁移到 RTX 4070 SUPER。当前代码已支持设备选择及模型/数据迁移，但未在该机器上实测；不记录未经测试的速度或显存峰值。

当前渲染器为每个点生成整张 S×S 的图。相同平均墨量下 N 约随 S² 增长，因此相关计算量 N×S² 约随 S⁴ 增长，边长翻倍约增加 16 倍。

按平均墨量 0.8、float32 估算，所有墨点软图的一份数据合计约为：

| 尺寸 | 点数约 | 数据量约 |
|---|---:|---:|
| 64×64 | 3277 | 0.05 GiB |
| 128×128 | 13107 | 0.80 GiB |
| 256×256 | 52429 | 12.8 GiB |

这不是实测总显存。训练还要保留求导数据，分块不等于释放全部计算图；调小 RENDER_CHUNK_SIZE 不能保证大尺寸训练一定可行。此前将分辨率翻倍仅描述为“计算量四倍”不适用于当前完整渲染流程。

继续扩展分辨率前，需要记录实际峰值显存和耗时，再考虑重计算、局部渲染或其他优化，并核对其梯度与数值行为。

## 11. 对旧笔记的纠正

- 当前进度已超出 Stage 1，进入单图训练原型和配置化工程阶段。
- 6400 个历史训练点的范围是 0～63.99；63.99 的普通 float32 表示不会因此 floor 成 64。当前整数编号生成标签也避免了该推测。
- ONet 测试准确率约 95.14%，未达到 100%，输出也未严格二值化。
- 可微渲染阶段的软图不应以“必须二值”作为已完成验收条件；硬落点结果需另外生成。
- PNet 未进行零输出初始化，不能要求或声称初始输出为零。
- 11×11、sigma=1.5 的训练平滑及 PNet 具体层级含工程选择。
- 不能将准确率低一概归因为学习率太小，也不能把“继续训练”当成必然解决方式。
- 旧笔记中数据集规模、固定迭代次数、目标 PSNR 等未在当前阶段落实的数字，不作为已验证进展或当前验收依据。
